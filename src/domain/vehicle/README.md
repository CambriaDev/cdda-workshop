# Vehicle domain (0.I-1)

Pure TypeScript and immutable edit/preview operations. No filesystem or save-write API is used by the domain. Game source and personal saves were read-only inputs during development.

## Public API

Import from [index.ts](./index.ts). Definitions use the shared structural contract `Definition { id: string; type: string; [key: string]: unknown }`. Pass `{ parts: Map<string, Definition>, items: Map<string, Definition>, flagRequirements?: Map<string,string> }`. The maps must contain the **active mod-order-resolved** definitions; this domain does not flatten inheritance or combine namespaces. Build `flagRequirements` from active `json_flag` definitions' `requires_flag` fields. Omitting that map causes explicit incomplete-dependency warnings.

- `createVehicle(name)`, `renameVehicle(vehicle,name)`, `partsAt(vehicle,x,y)`, `setPartVariant(vehicle,index,variant)`.
- `installPart(vehicle,{id,x,y,variant?},indexes)` and `removePart(vehicle,index,indexes)` return `{ vehicle, ok, issues }`; failed edits return an unchanged clone.
- `validateVehicle(vehicle,indexes)` checks installation order, structure/adjacency, duplicates, location/cargo conflicts, mirror/opaque conflicts, engine exclusion groups and supplied flag dependencies. It is **not full game validation**. Removal checks basic attachment/dependency/structural-split rules; dynamic animal, carried-vehicle and lock-state game interactions are not comprehensively simulated.
- `calculateStats(vehicle,indexes)` returns metric records `{ known, missing, complete, unit }`, not fictional zeroes for missing contributions. Weights use grams, capacities millilitres, power watts / hp. `known` is a known subtotal when `complete === false`. `missing` counts uncomputed contributions, not necessarily distinct parts. Actual power is explicitly unavailable, not the rated-engine sum. No speed, acceleration, consumption or range estimate is provided.
- `createProject(vehicle,metadata)`, `updateProject(project,vehicle,event?)`, `parseProject(input)`, `serializeProject(project)`. The project retains independent `original` and edited `vehicle` snapshots, metadata, ordered mods, history, warnings and unknown fields. Shared save lossless JSON preserves large integer and exponent tokens throughout clone/edit/project round-trips. Ordinary unsafe JS numbers are rejected rather than silently rounded. Projects are **editor-only** and cannot be injected into game saves.
- `getFuelChoices(vehicle,indexes)` reports per-part allowed options, proven capacities and unsupported reasons.
- `previewMigration(vehicle,{ includeCargo, condition:'preserve'|'new', fuelSelections?:Record<number,string> },indexes)` returns `{ vehicle, changes, issues, fullyRenewed }`. `changes` is a per-part field-level preview. Only `part.items` is cargo; installed tools and base contents are not stripped. The original vehicle is never changed. `new` clears serialized base `damaged`, `degradation`, and `faults`, not cargo item damage.
- `exportBlueprint(vehicle,{id?,modId?,dependencies?},indexes)` returns `{ prototype,modInfo,losses,files,gameValidated:false }`. `exportBlueprintZip` returns a `Uint8Array`. Official prototype fields only, stable prefixed auto-IDs, sanitized filenames and explicit loss report. Supply the real ordered dependencies: the domain does not guess mod ownership. Structurally invalid blueprints fail; unknown IDs remain exportable with warnings.
- `importVehicleFile(string|Uint8Array)` reads a project JSON, prototype JSON or this editor's blueprint ZIP. It returns `{vehicle,project?,issues}`. Prototype imports preserve the raw original under `importedPrototype` and per-part `blueprintSpawn`; they do not pretend probabilistic spawn instructions are actual save items. Re-export preserves supported fuel/ammo/tools and item spawn descriptions. Unsupported original fields remain in the project but may be absent from native blueprint output. ZIP import is bounded (16 MiB compressed / 32 MiB expanded / 8 MiB entry / 32 entries) and rejects unsafe paths and ambiguous vehicle entries.

## Explicit partial support

- **No game executable/import verification has been run.** Static TS tests are not game validation. Every export includes that warning.
- Refill supports only one directly installed `MAGAZINE` pocket with an exact `ammo_restriction` and a compatible recognized serialized pocket. Free fuel/ammunition choice is always explicit per part; an old/default ammunition type is never auto-selected. Fixed battery refill requires unambiguous battery ammunition data. Multi-pocket items, liquid tank volume/charge conversion, detachable magazines, nested fuel capacity and installed-tool refills are currently **unsupported**: retain their original contents/quantities, issue warnings and return `fullyRenewed:false`. The UI must not label these 'all full'.
- Composed definitions use `_incompleteFields:string[]` for field-level reliability (nested dotted paths are supported). Only relevant fields invalidate a calculation: e.g. inherited `to_hit`/`melee_damage` uncertainty does not invalidate an explicit frame weight, while `weight`, `flags`, charge-counting fields or `pocket_data` uncertainty affects the metrics/rules that actually depend on them. `_incomplete:true` without a valid field list, or a list containing `'*'`, remains conservatively unknown globally. Affected metrics carry missing counts/warnings; installation/removal rules do not assert untrusted flags/location/engine semantics, part-to-item associations are fabricated only when `item` is reliable, and refill never trusts unresolved capacity fields.
- Static weight supports ordinary base items, charge-counted ammo/non-solid comestibles/stackable items, known nested pockets and installed tools without double counting. `stack_size` is not a weight divisor. Corpse/craft state, runtime mass overrides, gun-modified base weights, ammo-belt linkages and extra-pocket weights are incomplete. Complex cargo volume, charge-counted cargo volume and container expansion rules are not guessed. Unknown IDs contribute missing counts.
- Durability follows serialized `base.damaged` (not an invented `part.hp`). 0.I-1 non-charge-counted item max damage is 4000, charge-counted max damage 0. Rated power excludes condition-dependent muscle/animal/wind contributions. Current engine power needs fueled/enabled state, damaged-power factor, faults, alternator load and multi-engine reduction and is deliberately unavailable.
- Blueprint output is lossy: exact damage/degradation/faults, fuel quantities, containers/complex cargo, ownership, passengers, world references and arbitrary mod state are not transferable as native vehicle prototypes. Top-level item IDs are retained as spawn descriptions; instance details are reported as lost. Full raw preservation requires the project format.
