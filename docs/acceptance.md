## 动力、能源与完整性：静态报告与新增验收场景

新增报告位于原有整车统计之后，区域名称为 **动力、能源与完整性 / Power, energy & completeness**，用途选择名称为 **校验用途 / Validation purpose**。`self-propelled`（自主行驶）检查驱动与驾驶组件；`passive`（非自驱或固定设施）将发动机、驾驶控制、车轮与转向要求标为不适用，不等于豁免游戏规则。缺失提示仅为建议，不新增导出阻断；报告、折叠状态和用途不写入项目或撤销历史。

### 静态含义与边界

- 发动机额定机械输出、全负载能源输入、标称电力负载、标称发电与机械负载分别显示；发动机负 `epower` 包含运行点火/ECU 耗电，不是仅启动耗电，启动浪涌另未模拟。其余操作可能有条件，不代表当前功率、实际油耗、净功率或续航。真实 `engine_electric_small` 为机械输出 **7040 W**、满载输入 **8000 W**，不把两者相加当耗电；`alternator_car` 标称发电 **780 W**、机械负载 **1492 W**。
- 电池标称容量、储罐标称容积和实例资源记录互不替代。真实 `storage_battery` 为 **50,000 充能单位 ≈ 13.89 kWh**；`tank` 的基础物品 `metal_tank` 有 **60 L** 水密容器口袋，外部体积 60.05 L 不是储罐容量。没有资源记录不表示空，也不表示满；没有因此扩大补满/迁移支持。
- 能源供应路径为有条件证据，不保证已有兼容燃料、足够电量、可用外部电网或可启动。兼容性同时考虑储存部件的精确 `fuel_type` 限定，不能只凭“有油箱”或弹药类别相同就通过；气体、等离子体的专门容纳条件不模拟，有潜在储罐路径时为未知而非缺失。驾驶 `CONTROLS` 与电子设备 `CTRL_ELECTRONIC` 不同；电子控制面板不能替代方向盘、油门及刹车。远程/动物操控、启动器、损伤、浮体承载与实际运行条件不静态冒充通过。
- 状态区分存在、缺失、有条件、未知、不适用；缺失定义或相关字段不可靠不折算为零。车轮检查仅识别完整设计组件（单个稳定车轮另受至多三个结构格限制）；不证明接地、负重稳定、船体浮力或道路可行驶性。
- 源码与真实定义出处见 [领域说明](../src/domain/vehicle/README.md)，包括游戏驾驶控制入口、电子/驾驶控制分支、单轮规则及真实马达、电池、油箱定义。现有安装/拆卸校验、无损项目和蓝图的限制保持独立。

## 系统分类合计与同型号折叠

本轮扩展原逐件报告，未修改项目、存档或导出格式，未增加依赖：

- 分类标题收起时仍显示部件数、型号数和主要总量；展开后显示发动机机械输出（W / kW / hp）、定义中的满载燃料／电能输入、全部支持储罐的标称总容积、电池标称总容量与单独的记录电量（charges / kWh）、全开名义用电／发电和机械负载。用电拆分为附件、发动机运行辅助、电驱满载及充电设备条件负载。
- 同型号按系统类别、部件 ID、实际／默认底层物品 ID 合并；同名不同 ID 或不同底层电池不混合。重复型号默认折叠，原生键盘／点击均可展开，每件部件的索引、坐标、额定值、启用／损伤／故障与储量提示保留。单件直接显示，合计逐件累加，不采用首件乘数量。

3. **复杂补满不臆造。** 只补能严格证明容量与结构的单 MAGAZINE 口袋；体积油箱、多口袋、可拆弹匣等保留原值并警告，不能声称整车全部全新化完成。
