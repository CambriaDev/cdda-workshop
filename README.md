# CDDA Workshop / 废土工坊

基于本地 **CDDA 0.I-1** 数据的独立、非官方、纯静态 React + TypeScript 编辑器。包含载具工坊、只读附近车辆查询、原生角色 TRANSFER 模板导出和可验证离线缓存。

> **重要：目前没有完成实际游戏导入验收。** 已核实源码结构、自动化测试和真实存档只读回归，不等于保证游戏加载成功。请在匹配版本、匹配模组、已备份的测试世界中验证。

## 运行

需要 Node.js 22.16+ / npm 10+。项目已经包含提取后的数据，普通开发和构建不需要游戏源码。

```powershell
npm ci --legacy-peer-deps
npm run dev -- --host 127.0.0.1
```

打开命令输出的 localhost 地址。不要直接双击 HTML。目录选择与 PWA 需要 HTTPS 或 localhost。Chrome / Edge 支持只读目录选择；不支持该 API 的浏览器仍可用普通文件选择导入项目、蓝图和角色 `.sav`。

也可以使用安装了 Docker Compose 的 Docker 一键构建并启动生产版：

```sh
docker compose up --build -d
```

访问 <http://localhost:8080>；停止并移除容器使用 `docker compose down`。服务仅绑定本机地址，不需要本机安装 Node.js。首次启动需要下载基础镜像和 npm 依赖；应用仍是静态站点，没有后端或存档上传服务。

```powershell
npm run check
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
npm run test:e2e
```

浏览器测试默认使用已安装的 Chrome（Playwright `channel: chrome`）；如机器没有 Chrome，安装 Chrome，或在 Playwright 配置中改用本机可用浏览器。测试生产构建，而不是 Vite 开发服务器。

## 使用

### 载具工坊

- 从空载具开始，或下拉加载真实数据中的原型；原型的随机生成描述不会被当成已经生成的实例。
- 左侧按中文、英文或 ID 搜索，按分类 / 模组筛选；点击部件后选择网格格子并安装。
- 选中部件即可查看双语详情：简介、空部件重量、额定耐久、发电／固定耗电／满载能耗、机械输出与马力占用、货舱／油箱／电池／弹药容量、工具能力等级及额定起重质量、伪工具与可连接工具、轮组、防护与舒适等。未知或未提供的值不按零处理；高级数据保留完整公共定义与来源。
- 工具能力不是角色技能，也不是安装要求。`JACK`／`LIFT` 每级额定 500 kg，`SELF_JACK` 单独解释；底层物品能力、伪工具能力与安装部件实际提供的能力不混为一谈。发电机的机械负载与发电量、电机的额定输出与满载耗电分列，不做整车净功率模拟。
- 待安装与已安装部件独立选择；已安装详情额外显示实际记录的损伤、老化、启用、内部储量和附加工具，不把缺失状态补成零，也不把额定容量当成现有燃料／电量。
- 车辆 **+X 朝前 / 向上，+Y 向右**。滚轮或按钮缩放，鼠标右键 / 中键拖动平移，箭头键移动选择；同格部件按安装顺序列出。外观变体可在检查面板修改。
- 安装和拆卸检查结构支撑、位置、连接、互斥与可识别依赖；不计算材料、工具或施工耗时，不宣称覆盖全部游戏安装规则。
- 统计中的 `*` 表示存在未知 / 未支持项，仅为已知小计，展开下方统计限制；不模拟驾驶物理或实际引擎运行功率。
- 公共数据解析缓存按解析器代码 / 源码提交 / 有序包与翻译哈希隔离，只保留最近一个组合，缓存不可用时照常解析。当前载具项目在此站点的 IndexedDB 自动保存；不是跨设备同步，也不是游戏存档。重要内容请手动导出备份。清除站点数据会删除草稿和偏好。
- 撤销 / 重做保留最近 50 次编辑，浏览器重开后不恢复撤销栈。

### 两类载具输出

**无损项目 / 迁移文件**：本编辑器回读的版本化 JSON，保留原始完整快照、编辑结果、未知字段、嵌套物品和大整数。不能注入游戏存档，不能直接在游戏生成。

**游戏蓝图模组 ZIP**：包含原生 `modinfo.json`、`vehicle.json`、损失报告和安装说明。解压到游戏识别的模组目录，在测试世界启用模组及其依赖，然后通过调试菜单按名称 / ID 生成；不是放进存档目录自动出现。损伤、精确燃料量、复杂货物等无法由原型表达的内容会报告损失，建议同时导出无损项目。**尚未游戏验收**。

迁移选项只作用于克隆：

- 排除货物仅移除 `part.items`，不会移除基础物品口袋内的燃料、电量与已装工具。
- 保留现状不重置部件状态。
- 全新化修复可识别基础物品损伤、老化与故障；货物本身不修复。非固定电池的燃料 / 弹药必须逐部件显式选择。
- 当前仅对能从数据严格证明的单 `MAGAZINE` 口袋执行补满；油箱体积、多口袋、可拆弹匣、复杂嵌套结构保留原量并警告，不能声称“全部补满”。

### 存档工作台

1. 先退出游戏并备份，再选择单个世界目录（包含 `mods.json`、角色 `.sav`、`maps/`）。浏览器仅请求 `read` 权限；没有写回接口。
2. 多个角色可切换。默认半径 60 小格、同 Z 层，按角色绝对位置至车辆锚点的平面欧氏距离判断，含边界。
3. 为避免不可靠文件命名导致漏车，当前默认 Worker 受控全扫世界地图，读取并发 2，并显示进度；不是将全部地图载入主线程。取消会真正终止 Worker 并释放完整存档，需要重新选择来源。
4. 大小 / 修改时间前后及扫描末尾变化会丢弃结果；这不是操作系统原子快照，无法识别被恢复为相同元数据的编辑，因此必须先退出游戏。出现解析失败会显示不完整警告。
5. 附近载具可作为副本进入载具工坊，再进行两类导出。进入载具工坊的快照会作为本地载具草稿保存，但整个角色 / 地图存档不自动持久化。
6. 普通 `.sav` 文件导入可以导角色模板，不具备地图扫描权限。

### 原生角色模板

输出原生 `[metadata, avatar]` 双对象数组，`metadata.limit = 3`（TRANSFER），不是任意角色 JSON / 改名的 `.sav`。将 `.template` 放入游戏实际用户目录下的 `templates`，在具备相同必要模组的新测试世界中选择预设。可自定文件名。

成长、装备、背包、嵌套物品与未知字段保留。默认清理已核实的旧世界坐标、任务 / NPC / 活动 / 载具关联；这是**编辑器策略**，并不是原生 `save_template` 自动清理。未知模组字段、物品所有权及嵌套关联可能仍存在，会警告。

**安全偏离原计划的限制**：健康重置默认关闭、必须显式启用；目前只能按存档现有 `hp_max` 恢复，并清理可识别的临时效果和部分状态，不是完整医疗模拟。永久 / 未知效果保留，维生素、热量、成瘾、温度、血液和模组机制不保证重置。不伪造“完全健康”，也不修改携带物品状态。实际转移行为与时间依赖数据仍需游戏验证。详见兼容文档。

其他存档数值编辑、地图 / NPC 编辑、目标存档注入不在本版范围。

## 真正离线

生产版点击页面底部 **准备离线使用**，等待明确显示“离线资源已校验并就绪”。首次联网只打开页面**不代表**离线可用。准备过程下载应用、Worker、全部已交付包、翻译与许可文件并逐一 SHA-256 校验，全部成功才写入就绪标记。随后可断网关闭页面并重新打开。

缓存按整个发布隔离（应用 / 数据 / SW 代码参与发布标识）。更新失败保留旧完整缓存；准备新版本全部成功才切换并清理旧发布。准备时需要新旧版本的临时双份空间。配额不足 / 浏览器清理缓存后会显示失败或未就绪，需重新准备；草稿仍应手动备份。开发模式不注册离线 Worker。

`npm run release` 会构建并生成 `release/cdda-workshop-0.2.0-static.zip` 及 SHA-256 文件，包含静态应用、完整交付数据、许可、部署说明和验收记录；不包含源代码、依赖安装目录或私人存档。解压后用静态服务部署即可，不必安装 Node 依赖。该命令只打包，不替代浏览器和游戏验收。

静态托管将 `dist/` 全部文件保持相对目录一起发布，HTTPS 部署，`sw.js` 与 `index.html` 推荐 `Cache-Control: no-cache`；哈希命名 `assets/*` 可长期缓存。支持部署到子目录。资源更新要构建完整版本并原子发布目录，不能先替换一半数据再覆盖页面。若曾试用其他部署，服务工作线程只管理当前 scope 下的应用资源。

## 数据、提取与许可

- 固定来源：0.I-1 / commit `7b2efa5cea38e4d4d97dd0e63b28b9148623da59`；目前只有这个真实数据版本，不提供空版本占位。
- 12 个可分发包、30,804 条原始定义；核心包 20,863 条（包含工具能力定义与其上下文翻译）。抽象定义不直接供安装。已交付不等于已启用：在数据页显式编辑组合、检查依赖并应用。
- 28 个第三方目录全部有审计记录；仅 `blazemod` 有已确认许可可分发，另 27 个仅提供报告、不打包其原始内容。
- 不把 `No_Fungi` 冒充不存在的 `no_fungal_growth`，不把缺失的其他模组替换为“相似” ID。
- 对未支持的继承 / finalize 语义给出诊断与 `_incomplete` 标记，不用通用深合并伪造游戏加载器。
- 真实游戏数据遵循 **CC BY-SA 3.0**，来源、署名、许可证与翻译致谢在 `public/datasets/0.I-1/`，随部署离线交付。新增模组必须先确认许可。应用代码目前不另行作开源授权承诺；依赖遵循各自许可证，构建时生成并随离线发布交付 `THIRD-PARTY-NOTICES.txt`。

从此工作区父目录的只读源码 / 模组重提取（选项见工具）：

```powershell
npm run extract
npm run build
```

提取器只写项目 `public/datasets`，不修改游戏源码、模组或存档。变更数据后必须重建生产发布。详细证据与边界见 [数据报告](docs/datasets.md)、[兼容报告](docs/compatibility.md)、[载具领域说明](src/domain/vehicle/README.md)。
